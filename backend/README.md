# Dispatcher auf Uberspace

Auf Styx eine freigegebene Release-Kopie und ein privates Datenverzeichnis anlegen. Python 3.14 ist auf dem Host vorhanden. Im Release-Verzeichnis `python3 -m venv .venv` und `.venv/bin/pip install -r requirements.txt` ausführen. Eine private Kopie von `.env.example` als EnvironmentFile mit Modus 0600 pflegen. Für Benutzer und Agent zwei getrennte zufällige Tokens mit jeweils `openssl rand -hex 32` erzeugen. Die DB auf einen absoluten Pfad außerhalb des Release-Verzeichnisses setzen.

Als systemd-User-Service mit `WorkingDirectory` auf `backend/`, `EnvironmentFile` auf die private Datei und `ExecStart` auf den absoluten Pfad zu `.venv/bin/uvicorn app:app --host 0.0.0.0 --port PORT` einrichten. Einen freien Port und eine freigegebene Route wählen. `systemctl --user daemon-reload` und `systemctl --user enable --now claude-remote.service` ausführen. Die gewählte Route mit dem Uberspace-Frontend verbinden. Vor Freigabe ein gültiges Zertifikat, `/api/v1/health` und einen authentifizierten Abruf über HTTPS prüfen. Dienstlaufzeit über Logout und Hostneustart separat bestätigen. [Uberspace Web Backends](https://manual.uberspace.de/web-backends/)

Für APNs separate User-Unit mit demselben Arbeitsverzeichnis und EnvironmentFile sowie `ExecStart=.venv/bin/python push.py` als absolutem Pfad einrichten. Einen Worker je DB betreiben. Erst starten, wenn die API-Migration lief und das Apple-Zertifikatsprofil, der APNs-Schlüssel, Topic und Umgebung feststehen. Das Payload enthält einen generischen Alert und eine UUID. Der Worker wiederholt transient fehlgeschlagene Versuche und verwendet für Wiederholungen dieselbe Collapse-ID. Versand ist at-least-once. [Apple APNs Provider API](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)

Beim Update beide eigenen Units stoppen, die Datenbank sichern und das alte Release erhalten. Das neue Release mit separater venv vorbereiten, Unit-Pfad wechseln, API starten und Healthcheck abwarten. Danach Worker starten. Bei Rollback beide eigenen Units stoppen, auf das frühere Release zurückschalten und bei inkompatibler Migration die gesicherte Datenbank wiederherstellen. Bei einer Datenbankwiederherstellung gehen zwischenzeitliche neue Einträge verloren. Den Wiederherstellungszeitpunkt vorab klären.

Lokal im Backend-Verzeichnis `python -B -m unittest -v` ausführen. Die Live-Spezifikation steht unter `/openapi.json`.
